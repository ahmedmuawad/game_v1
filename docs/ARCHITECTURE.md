## 1. المكدّس

| الطبقة | التقنية | لماذا |
|---|---|---|
| الواجهة | React 19 + TypeScript | واجهة كثيفة وحركة معقّدة |
| البناء | Vite 7 | إقلاع سريع وحزم صغيرة |

## 3. مبادئ معمارية

### 3.1 المنطق منفصل عن الواجهة
كل ما في `systems/` دوال نقية أو وحدات بلا React. محرك القصص مثلًا بياخد
الفصل والسياق ويرجّع العقدة التالية والآثار — **بلا أي وصول للمخزن**.
النتيجة: يُختبر بلا DOM، ويمكن تشغيله في أدوات التحقق من المحتوى.

### 3.2 المحتوى بيانات لا كود
القصص والعناصر والأزياء كلها JSON تُحمَّل وقت التشغيل. السبب عملي:
**إضافة فصل أو قطعة جديدة لا تحتاج تحديثًا في المتجر** — وده شرط لخطة
نزول المحتوى المتكرر اللي الاحتفاظ قايم عليها.

### 3.3 مصدر حقيقة واحد للأصول
`tools/avatar/wardrobe.py` بيولّد الصور و `manifest.json` معًا. اللعبة
تقرأ الـmanifest. مستحيل يحصل انحراف بين عنصر وصورته.

### 3.4 offline-first
لا تسجيل دخول ولا حساب. الحالة كلها في `localStorage` مع إصدار مخطط
وترحيل. المزامنة السحابية ميزة لاحقة اختيارية (DECISIONS.md#D-006).

### 3.5 لا نصوص في المكوّنات
كل نص يواجه اللاعب له مفتاح في `i18n/strings.ts` أو حقل `{ar, en}` في
المحتوى. التنسيقات تستخدم خصائص CSS المنطقية حصريًا، فالـRTL يعمل بلا
كود إضافي.

## 5. خط إنتاج الشخصيات (3D → طبقات 2D)

```
base.obj (MakeHuman, CC0)
   ↓ character.py      تطبيع + تنميط + تسطيح الصدر
   ↓ face_shape.py     15 معاملًا للملامح → شخصيات مختلفة
   ↓ expression.py     فتح العين + التعابير
   ↓ eyes.py           كرة بملاءمة + قزحية وبريق
   ↓ hair_cards.py     بطاقات خصل + فروة
   ↓ garments.py       قطعة = منطقة جلد مُزاحة + تنعيم لابلاسي
   ↓ blender_util.py   إضاءة استوديو + Cycles
   ↓ export_layers.py  طبقات WebP بنفس الكاميرا + manifest.json
   ↓
public/avatar/  →  AvatarView.tsx (تركيب صور)
```

**لماذا صور لا 3D لحظي:** التشغيل بيبقى تركيب صور، فبيشتغل بسلاسة على
أرخص أندرويد وبلا استهلاك بطارية داخل WebView على iOS — وده كان أهم
تحفّظ تقني على المسار كله.

## 6. الأداء

| الهدف | القياس الحالي |
|---|---|
| حجم حزمة JS | 369 KB (120 KB مضغوطة) |
| حجم CSS | 19 KB (5 KB مضغوطة) |
| متوسط طبقة الأفاتار | 6.9 KB (WebP) |
| زمن البناء | ~2.5 ث |

**قواعد:**
- الحركة على `transform` و `opacity` فقط.
- `memo` على مكوّنات الأفاتار (تُعاد كثيرًا في القوائم).
- الفصول تُحمَّل عند الطلب مع تسخين الفصل التالي.
- تركيب الأفاتار عبر `<img>` مستقلة — المتصفح يخزّنها مؤقتًا ويعيد
  استخدامها عبر الشاشات.

## 7. حدود الاختبار

| المكوّن | كيف يُختبر |
|---|---|
| محرك القصص | دوال نقية + `validateChapter` يفحص كل فصل |
| الاقتصاد والطاقة والتقدّم | دوال نقية بلا حالة عامة |
| الواجهة | لقطات شاشة آلية (`tools/qa/screenshot.mjs`) |
| مسار القصة كاملًا | تشغيل آلي (`tools/qa/story-run.mjs`) |
| المحتوى | مدقّق الرسم البياني يكشف المراجع المكسورة والحلقات |

## 8. المسار للنشر الأصلي

1. `npm run build`
2. `npx cap add ios && npx cap add android`
3. إضافات: `@capacitor-community/admob`، `@capacitor/haptics`،
   `@capacitor/preferences`، شراءات داخل التطبيق
4. **إلزامي:** تهيئة AdMob في وضع غير مخصّص وموجّه للأطفال قبل أي طلب
   إعلان (`DECISIONS.md#D-002`)
5. رفع من Xcode / Android Studio
